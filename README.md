# ai-proxy-bootstrap

Локальный прокси на Debian, через который ходят **только выбранные домены** — по умолчанию
AI-провайдеры. Всё остальное идёт напрямую: Telegram, SSH, внутренние адреса, обычный браузер
маршрут не меняют.

Под капотом [v2rayA](https://github.com/v2rayA/v2rayA) + его встроенное ядро. Веб-интерфейс
поднимается, но заходить в него не нужно: всё настраивается двумя скриптами.

## Установка

```bash
git clone https://github.com/nasdion/ai-proxy-bootstrap.git
cd ai-proxy-bootstrap
sudo ./install.sh
```

Скрипт ставит пакет, проверяет контрольную сумму, привязывает админку к `127.0.0.1`,
заводит админский аккаунт (пароль — в `/etc/ai-proxy/admin.secret`, 0600) и вызывает `apply.sh`.
Никаких ключей внутри скриптов нет.

## Где что лежит

| | |
|---|---|
| **Домены** | `domains.list` — в этом репозитории, под git |
| **Ключи и подписки** | `/etc/ai-proxy/servers.list` — только на машине, 0600, **в git не кладём** |
| Пароль от админки | `/etc/ai-proxy/admin.secret`, 0600 |

### Ключи

`/etc/ai-proxy/servers.list`, по одной записи на строку. Работает и то, и другое:

```
vless://...          отдельный сервер (vmess/trojan/ss/hysteria2 тоже понимает)
https://.../sub      URL подписки — развернётся во все её серверы
```

Серверов может быть сколько угодно. Повторный запуск `apply.sh` уже добавленное не дублирует.

### Домены

`domains.list`, по одному матчеру на строку — `domain:` (домен со всеми поддоменами),
`full:` (точное имя) или `geosite:` (готовый список из geosite.dat).

## Ежедневное

```bash
sudo ./apply.sh                  # применить домены и серверы (после любой правки)
sudo ./apply.sh --list           # какие серверы есть и какой сейчас активен
sudo ./apply.sh --server ams-1   # переключиться на другой сервер (по имени или номеру)
sudo ./apply.sh --update-subs    # обновить подписки
```

Добавить провайдера — дописать строку в `domains.list` и запустить `sudo ./apply.sh`.
Переустановка не нужна, соединение не рвётся.

## Как этим пользоваться

Прокси не системный: он ничего не перехватывает, пока в него явно не направят. Направляем
конкретную программу:

```bash
HTTPS_PROXY=http://127.0.0.1:20171 \
HTTP_PROXY=http://127.0.0.1:20171 \
ALL_PROXY=socks5h://127.0.0.1:20170 \
codex
```

Важно: даже эта программа пойдёт через туннель **только на домены из `domains.list`** —
остальное она возьмёт напрямую. То есть направить в прокси можно смело, «случайно увести
весь трафик» не получится.

`socks5h`, а не `socks5`: с `socks5` имя резолвится локально и до прокси доезжает голый IP,
по которому правила уже не срабатывают.

Проверка (её же печатает `apply.sh`):

```bash
curl -I --proxy http://127.0.0.1:20171 https://api.openai.com/v1/models   # ждём HTTP/2 401
curl -I --proxy http://127.0.0.1:20171 https://example.com                # ждём 200, напрямую
```

`401` — правильный ответ: до OpenAI дошли, ключа не дали.

## Что специально не включено

- **TUN / прозрачный прокси** — выключен. Весь хост в туннель не заворачивается.
- **Системный прокси** (`/etc/environment`) — не трогается.
- Порты `20170` и `20171` слушают только `127.0.0.1`, наружу не торчат.

Если позже захочется системного уровня — правила уже описаны, останется включить transparent
в v2rayA. Отдельная задача, отдельное решение.

## Мелочи, на которые можно наступить

- В v2rayA **два вида инбаундов**. Обычные SOCKS5/HTTP гонят в туннель *всё* и правила
  игнорируют; правила применяет только пара «с правилами». `apply.sh` обычные выключает и
  отдаёт номера `20170/20171` тем, что с правилами, — поэтому привычные порты ведут себя
  ожидаемо.
- Пока не выбран сервер, ядро не запущено и портов `20170/20171` **не существует** —
  `curl --proxy` ответит connection refused. Это не поломка.
- DNS-слушатель v2rayA по умолчанию поднимается на `0.0.0.0:52353`, то есть открытым
  резолвером на всю сеть. `apply.sh` прижимает его к `127.0.0.1`.
- `domain:openai.com` уже покрывает `api.openai.com` и `auth.openai.com` — отдельные `full:`
  для них не нужны.
- `domain:googleapis.com` в списке намеренно нет: под этим зонтом живёт половина сервисов
  Google, и в туннель уехало бы много лишнего. Для Gemini достаточно
  `full:generativelanguage.googleapis.com`.
- GitHub оставлен напрямую. Правило для него не нужно вообще: что не перечислено — идёт мимо
  прокси.
